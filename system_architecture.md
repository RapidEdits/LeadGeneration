# Prospecting and campaign email reporting

- Product profile: `LeadSource.kind=product_profile`; validated settings in `meta.profile`, encrypted optional Brave key in `meta.search_key`. One profile per workspace is serialized using a Workspace row lock. Never return the encrypted key or plaintext to the client.
- Discovery run: `LeadSource.kind=prospect_discovery`; JSON metadata snapshots profile/settings, queued/running/completed/failed state, counters, source evidence and up to 100 candidates. Celery task `prospecting.discover` runs on the existing worker. At most one recent running job per workspace; stale jobs are displayed as failed after 15 minutes without progress. No automatic repeat of a run's external queries.
- `public_web.py`: validates every resolved address, pins connections to a public IP while maintaining Host/TLS validation, checks robots for redirect destinations, bounds download size/time and redirects, parses visible HTML plus JSON-LD coordinates with stdlib.
- Geography: named-location evidence is matched on fetched pages, not trusted from query hints. Radius is strict against published coordinates; unknown coordinates fail the radius filter. AI fit uses the existing `qualify_lead` contract and can never invent contact emails or overrule location filtering.
- Import: lock workspace/run, validate selected candidate IDs, skip suppressed addresses, reuse existing email matches, create Companies/Leads with observed email provenance and evidence, and reuse `campaign_service.add_leads`. Enrollment only into draft/paused/scheduled campaigns; launch remains a separate user action.
- Sender: all campaign sends still pass `can_send`. Schedule/frequency/daily-limit waits do not consume provider-failure attempts. `tick` locks campaign rows with SKIP LOCKED, serializing concurrent ticks per campaign.
- Email analytics: `/analytics/email` accepts campaign/date filters and aggregates distinct normalized observed events per outbound email. It reports real provider acceptance separately from simulations/queue/failure, and attributes engagement to the email's creation-date cohort. Workspace analytics share the real-send definition in `message_metrics.py`.
- Inbox: backward-compatible inbound default; added campaign/channel/direction/status filters, offset pagination, campaign names and scoped event histories. Frontend provides campaign folders via the selector and outbound/reply views.
- Test coverage: `backend/tests/test_prospecting.py` exercises parsing, public-network validation, robots/redirect handling, radius, search contract, tenant/RBAC checks, persistent progress, dedup/suppression, simulated campaign sending, concurrent ticks and metric counts. Do not run independent pytest processes simultaneously: their shared test fixtures recreate the same test schema.
